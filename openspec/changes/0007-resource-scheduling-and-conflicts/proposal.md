## Why

Phase 6 generates a tournament's fixture graph but assigns no venue, official, or time slot to any
fixture — a fixture exists structurally before it has a "when" or "where." `../chaos-vault/
50-research/copalibre-market-segment-feature-specification.md` lists "Resource-aware scheduling with
conflicts, rest rules, downstream-impact preview, and atomic publication" as one of the six P0
capabilities that "must ship together as the release gate" (TMS-005). Without it, an organizer could
generate a bracket but never produce a schedule an operator or spectator could actually follow.

## What Changes

- Implement venue/official/time-slot assignment for fixtures generated by phase 6.
- Implement conflict detection: double-booked venue, double-booked official, and configurable
  rest-rule violations (minimum time between an entrant's consecutive fixtures).
- Implement a **downstream-impact preview**: before committing a schedule change, show which
  already-published fixtures, notifications, or public views would be affected.
- Implement **atomic publication**: a schedule (or a batch of schedule changes) either publishes in
  full or not at all — no partially-applied schedule is ever visible to the public surface.
- Classify schedule mutations using phase 2's mutation model (`safe` for an unpublished draft
  change, `requires_rebuild` when downstream fixtures must be re-previewed, `blocked_after_results`
  once a scheduled match has already started or concluded).
- Explicit non-goal: no live match operation — this phase only assigns *when/where*, not match
  state. Phase 8 operates the match once its scheduled time arrives.

## Capabilities

### New Capabilities
- `resource-scheduling`: venue/official/time-slot assignment with conflict detection, rest-rule
  enforcement, downstream-impact preview, and atomic publication for tournament fixtures.

### Modified Capabilities
(none)

## Impact

- **New files/dirs**: `packages/domain/scheduling/`, `apps/api` scheduling controllers/endpoints.
- **Depends on**: phase 6 (fixtures to schedule), phase 4 (persistence for venues/officials/
  schedule state), phase 2 (mutation classification).
- **Unblocks**: phase 8 (a match's live-operations flow assumes a published schedule slot exists);
  phase 16's bracket/seeding UI and phase 12/13's public surfaces display the published schedule.
